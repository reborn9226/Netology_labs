### Задание 1. Резервное копирование

### Кейс
Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования.

Необходимо описать, какие варианты резервного копирования подходят в случаях:

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

*Приведите ответ в свободной форме.*

---
### Решение 1
1.1  Тут подойдет любое резервное копирование как и full backup так и остальные инкриментные и дифиренциальные. Так же можно копию из реплики делать, что бы не останавливать работу пользователей. Но тут лучше подойдет полная копия или диференциальная, быстрее восстановится. Главное что бы backup делался каждую ночь.

1.2 Тут подойдет диференциальное резервное копированее при условии если копии делаются каждый час или снапшоты файловой системы. Или иползовать бэкап логов транзакции. Каждые сутки полный бэкап базы и каждый час копируются только логи транзакций. При поломке мы разворачиваем ночной полный бэкап и последовательно накатываем на него логи вплоть до нужного часа.

1.3 Да, возможно. Для этого испольют отказоустойчевые кластера с автоматическим переключением (Keepalived или Patroni для PostgreSQL). Специальные утилиты каждую секунду проверяют живая ли база, если нет то переключают на резервную. Или использовать реплика master-slave c синхронной репликацией. При падении мастера, слейв мгновенно назначается новым мастером.

2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?

*Приведите ответ в свободной форме.*

---
### Решение 2
2.1
- Пример с pgdump
```bash
pg_dump mydb > db.sql # Выгрзка базы в sql скрипт
pg_dump -Fc mydb > db.dump # Выгрузка базы в дамп
pg_dump -Fd mydb -f dumpdir # Выгрузка базы в каталог
pg_dump -Fd mydb -j 5 -f dumpdir # Выгрузка базы в каталог использую несколько ядер процессора. Мой самый любимый backup использую на работе.
```
- Пример pgrestore
```bash
dropdb mydb # удаляем базу
pg_restore -C -d postgres db.dump # удаляем существующую базу данных mydb и ее востанавливаем в новую базу с тем же именем

createdb -T template0 newdb # Клонируем пустую базу из шаблона с новым именем
pg_restore -d newdb db.dump # И в нее же восстанавливаемся

```

2.1* Приведу в пример рабочего скрипта котрый делает fullbackup базы 1с каждую ночь и запускается при помощи cron. Так же после выполнения резервного копирования идет reindex баз данных и vacuum.

### Задание 3. MySQL

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?

*Приведите ответ в свободной форме.*

---
### Решение 3

3.1 У mysql есть платная версия субд и бесплатная. В бесплатной версии инерементные копии делаются через Бинарные логи куда записываютя все изменения.
```bash
mysqldump -u root -p --all-databases --single-transaction --master-data=2 > /backup/full_backup.sql # сначала делается полная копия
mysqladmin -u root -p flush-logs  # создание инкрементной копии
cp /var/lib/mysql/mysql-bin.0000XX /backup/incremental/  # копирование копии в папку с бэкапами
```
3.1* Реплика это не Бэкап, и это не однократно произносилось на лекциях, но использование реплики дает несколько преимуществ.
 - backup с реплики. Позволяет выполнять копию не нагружая основную базу и пользователи не замечают снижения скорости работы субд.

 - Реплика позволяет мгновенно переключатся на slave с мастера при аварии и slave становится мастером.

 - Реплику можно использовать для полезной нагрузки. Реплику можно использовать для тяжелых отчетов, аналитики, и посиковых запросов, что бы рагрузить основную базу.
